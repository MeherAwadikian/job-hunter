# Contra — blocked by a paywall, not a technical/API problem

- **Acquisition method:** None currently usable, for a reason distinct from every other connector in this system.
- **Official public API:** Exists (`contra.com/public-api/`, X-API-Key auth, hosted MCP at `contra.com/mcp`) — confirmed real (401 on an unauthenticated probe). But checking it in-depth on 2026-10-05: this API is for the **hiring side** — client accounts searching freelancer profiles to hire, not freelancers browsing job postings. Wrong direction for job-hunter's purpose even if a key were obtained.
- **Authenticated account check (2026-10-05):** The user already has a Contra account (`meher_awadikian_p2vsq70g`, independent/freelancer). Checked the actual jobs feed (`contra.com/jobs`) while logged in: **213 job postings exist, but the free account can only see/apply to 3 of them** — the rest sit behind a "Upgrade to Pro" paywall shown directly on the page.
- **Why nothing was built:** This isn't a scraping, CAPTCHA, or API-access problem — it's a straightforward paid-subscription gate on Contra's own platform. Upgrading to Contra Pro is a real monetary decision for the user to make, not something to route around or build infrastructure against.
- **What would unblock it:** The user deciding whether Contra Pro is worth subscribing to, independent of job-hunter's build. Once (if) that happens, the 213-job feed would be visible, and a Claude-in-Chrome pull (same pattern as Glassdoor/Upwork) could surface them — again not a standalone CLI connector, for the same reason: Claude-in-Chrome can't be invoked by job-hunter's own unattended code.
